# Информационная архитектура

Информационная архитектура описывает продуктовые сущности и их связи. Она не определяет реализацию, технологии или структуру хранения.

## Основные сущности системы

| Сущность | Назначение | Владелец или источник |
| --- | --- | --- |
| Посетитель и сессия | Даёт начать путь без регистрации и удерживает незавершённое прохождение в согласованный срок. | Пользователь / временная сессия |
| Пользователь и профиль | Даёт постоянный доступ к сохранённым результатам, настройкам и управлению данными. | Пользователь |
| Согласие | Фиксирует отдельное разрешение на обработку выбранных данных, хранение записи, использование портрета в совместимости и обучение на данных. | Пользователь |
| Выбор модулей | Определяет состав конкретного прохождения и нужные для него шаги. | Пользователь |
| Прохождение портрета | Объединяет ответы, дату рождения, необязательную запись и статус прохождения. | Пользователь |
| Ответ на вопрос | Выбранный вариант ответа; свободное дополнение существует только как необязательная часть ответа. | Пользователь |
| Голосовая запись | Исходная запись подготовленного текста для выбранного голосового модуля. | Пользователь |
| Анализ речи | Базовые наблюдения о качестве и особенностях текущей записи без идентификации и чувствительных выводов. | Вычисляется системой |
| Данные рождения | Дата рождения для нумерологических и зодиакальных интерпретаций. | Пользователь |
| Интерпретационный блок | Нумерологический или астрологический слой с явной маркировкой происхождения. | Вычисляется системой |
| Интересы и обратная связь | Добровольные данные для более уместного портрета и оценки полезности результата. | Пользователь |
| Персональный портрет | Связный результат выбранного прохождения: бесплатная часть, полный разбор, рекомендации и метки происхождения выводов. | Вычисляется системой на основе данных пользователя |
| Доступ к полному разбору | Подтверждает право открыть полный результат после оплаты. | Связан с пользователем или сохранённым портретом |
| Карточка публикации | Ограниченное представление результата для сохранения или добровольной публикации. | Формируется из портрета по выбору пользователя |
| Приглашение совместимости | Приватное приглашение второго человека в сравнение двух портретов. | Инициатор приглашения |
| Согласие на совместимость | Отдельное согласие каждого участника на использование указанных данных в общем результате. | Каждый участник |
| Разбор совместимости | Бережное сравнение двух портретов после согласия обоих; не содержит вердикта или единого процента. | Вычисляется системой |
| Запрос на удаление | Действие пользователя по удалению исходной записи, портрета, профиля или всех данных. | Пользователь |

## Связи между сущностями

- Посетитель создаёт временную сессию и одно или несколько незавершённых прохождений.
- Зарегистрированный пользователь связывает с профилем свои сохранённые прохождения, согласия, портреты, доступы к полному разбору и настройки.
- Одно прохождение содержит выбор модулей, ответы, дату рождения и, при выборе пользователя, голосовую запись, интересы и обратную связь.
- Голосовая запись создаёт анализ речи; исходная запись по умолчанию удаляется после анализа, если пользователь отдельно не выбрал её сохранение.
- Выбранные пользовательские данные и вычисляемые блоки формируют один персональный портрет. Портрет может иметь бесплатную и полную части.
- Карточка публикации является производной от портрета и содержит только выбранный для публикации объём данных.
- Приглашение связывает инициатора и второго человека. Разбор совместимости создаётся только при явном согласии обоих на выбранный объём данных.
- Запрос на удаление удаляет или прекращает доступ к зависимым сущностям в пределах данных, которыми владеет пользователь; детали каскадного удаления — открытый вопрос.

## Жизненный цикл пользовательского портрета

1. **Черновик.** Пользователь начинает путь как гость или в профиле и выбирает модули.
2. **Сбор данных.** В черновик добавляются ответы, дата рождения и необязательная голосовая запись; пользователь видит прогресс и может вернуться к предыдущему вопросу.
3. **Проверка ввода.** Некачественная или прерванная запись предлагается к повтору, но не блокирует портрет; неверная дата требует исправления или отключения связанного модуля.
4. **Создание результата.** Система рассчитывает доступные блоки и формирует бесплатную часть портрета с обозначением происхождения выводов.
5. **Знакомство с результатом.** Пользователь читает бесплатный результат, может дать обратную связь, сохранить его или создать карточку публикации.
6. **Полный разбор.** После успешной оплаты открывается доступ к расширенной части портрета. Отказ или ошибка оплаты не закрывают бесплатную часть.
7. **Сохранение и возвращение.** Регистрация предлагается при сохранении, оплате, постоянной ссылке или совместимости; гость может завершить путь без неё в пределах временной сессии.
8. **Совместимость.** Сохранённый портрет может стать частью совместимости только по отдельному согласию участника.
9. **Удаление.** Пользователь может удалить запись, портрет, профиль и все свои данные. Доступ к связанному общему результату прекращается в зависимости от удалённых данных.

## Данные пользователя

Пользователь добровольно предоставляет только данные, нужные для выбранных модулей:

- выбранные варианты ответов и необязательные комментарии;
- подготовленную голосовую запись, если выбрал голосовой модуль;
- дату рождения;
- интересы и обратную связь о результате;
- данные профиля, если решил зарегистрироваться;
- согласия и решения о хранении исходной записи;
- данные другого человека только в ограниченном предварительном сценарии совместимости без голоса и без создания его профиля.

По голосу нельзя определять национальность, религию, сексуальную ориентацию, здоровье или политические взгляды. Голос не используется для идентификации человека. Чувствительные данные не должны попадать в логи.

## Вычисляемые системой данные

- статус прохождения и доступность следующих шагов;
- базовые наблюдения по текущей голосовой записи;
- нумерологические и зодиакальные интерпретации;
- объединённый персональный портрет, его бесплатная и полная части;
- персональные рекомендации;
- доступ к полному разбору после успешной оплаты;
- статус приглашения и согласий на совместимость;
- разбор совместимости: сильные стороны, различия, темы для диалога и практические советы;
- карточка публикации из явно разрешённых пользователем частей результата.

Каждый значимый вывод должен иметь понятное происхождение: запись, ответы, модель саморефлексии, гипотеза, нумерологическая или астрологическая интерпретация, рекомендация.

## Временные сущности

- незарегистрированная сессия;
- черновик прохождения;
- неподтверждённая голосовая запись и её проверка качества;
- процесс создания результата;
- незавершённая оплата;
- неиспользованное или ожидающее приглашение совместимости;
- ограниченное предварительное сравнение по базовым данным другого человека;
- временная карточка перед сохранением или публикацией.

Срок хранения временных сущностей не утверждён и должен быть определён до запуска.

## Постоянные сущности

Постоянными становятся только объекты, для которых есть основание хранения: профиль, сохранённый портрет, явное согласие, доступ к полному разбору, настройки, сохранённая карточка публикации и совместный результат с согласием обоих участников. Исходная голосовая запись не является постоянной по умолчанию.

## Состав MVP

В MVP архитектура включает:

- гостевую сессию и профиль для сохранения результата;
- выбор модулей, быстрые ответы, необязательный голосовой модуль и дату рождения;
- базовый анализ речи, нумерологический и зодиакальный блоки;
- бесплатную и платную части персонального портрета;
- карточку для сохранения или публикации;
- приватное приглашение и базовый разбор совместимости романтической пары при согласии обоих;
- настройки и удаление голосовой записи, пользовательских данных и профиля.

## Будущие сущности после MVP

- специализированные режимы совместимости для дружбы и рабочих отношений;
- сложная натальная карта с отдельной обработкой времени рождения;
- тематические рекомендации по интересам;
- регулярные поводы вернуться и связанные пользовательские предпочтения;
- расширенная персонализация формата и тона портрета;
- версии и сравнение изменений портрета только при понятном пользовательском контроле.

## Information Architecture Principles

- Минимальная глубина навигации.
- Максимум два клика до основного действия в доступном контексте.
- Отсутствие тупиков: у каждого экрана есть понятное продолжение, возврат или безопасный выход.
- Последовательное раскрытие возможностей после появления ценности.
- Пользователь всегда понимает своё положение внутри продукта, прогресс и следующий шаг.
- Единая логика переходов: назад возвращает к предыдущему контексту, пропуск сохраняет выбор, а сохранение и публикация не меняют результат без явного действия пользователя.
