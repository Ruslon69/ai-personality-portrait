# Аудит Sprint 2.5

## Статус

Технический и UX-аудит frontend завершён. Критических дефектов не найдено. Безопасные исправления внесены без изменения утверждённого пользовательского пути, маршрутов и состава MVP.

Готовность к Sprint 3 — условная: текущий локальный интерфейс можно развивать дальше, но до подключения backend и AI необходимо определить единый контракт черновика портрета и передачу данных между шагами.

## Что проверено

- слои `app`, `pages`, `features`, `widgets`, `entities`, `shared`, `router`, `providers`, `store`, `services` и `styles`;
- публичные API модулей, направления импортов и циклические зависимости;
- базовые компоненты дизайн-системы и их HTML-семантика;
- локальное состояние вопросов, голоса, даты рождения, генерации, результатов, профиля, истории и настроек;
- все утверждённые маршруты и обработка неизвестного URL;
- управление фокусом, клавиатурная навигация, landmarks, нативные контролы, live regions, progress, drawer и dialog;
- адаптивные правила для узкого мобильного экрана, tablet, desktop и ultra wide;
- поведение при масштабировании текста и потенциальное переполнение длинных русских строк;
- таймеры, подписки, `MediaStream`, Web Audio и `Object URL`;
- разделение демонстрационных данных, типы моделей и готовность UI к замене локальных источников;
- размер production bundle, неиспользуемые стили и повторяющиеся CSS-паттерны;
- возможность отдельно проверять чистую логику без DOM и browser API.

Backend и существующая продуктовая документация не изменялись.

## Шкала серьёзности

- **critical** — блокирует основной путь, создаёт риск потери или раскрытия данных либо делает приложение недоступным;
- **high** — существенно мешает стабильности, доступности или будущей интеграции;
- **medium** — создаёт заметный технический долг или локальный UX-риск;
- **low** — не блокирует путь, но ухудшает единообразие или сопровождаемость.

## Исправленные проблемы

### Архитектурные границы

- Добавлен отдельный публичный вход `router/navigation` для провайдера и навигационного hook.
- Pages и widgets больше не импортируют root-barrel роутера, который одновременно загружает таблицу страниц.
- Theme switcher и settings используют узкий публичный API theme provider вместо root-barrel `app`.
- Header импортирует конкретный feature, а не общий barrel всех features.
- После изменений статический граф содержит 295 TypeScript-файлов, 597 внутренних связей и 0 циклов.

### Routing и focus

- Повторный переход на текущий pathname больше не создаёт дубликат в history.
- После смены маршрута фокус переносится в основное содержимое, если целевая страница не установила более точный фокус сама.
- Повторяющаяся установка фокуса вынесена в общий helper, который отменяет незавершённый animation frame.
- Существующие более точные переходы фокуса на заголовок вопроса, результата, профиля, истории и настроек сохранены.

### Надёжность

- Добавлен доступный fallback для необработанной ошибки рендера.
- Пользователь получает краткое объяснение и действие для перезагрузки вместо пустого экрана.
- Переданное извне значение `fallback`, включая `null`, сохраняет прежнее поведение.

### Accessibility и responsive

- Dialog получает внутреннюю вертикальную прокрутку при ограниченной высоте.
- Ошибка даты использует один согласованный alert-режим.
- Оценка качества голоса больше не создаёт вложенное повторное live-объявление.
- UI по-прежнему не зависит только от цвета: статусы сопровождаются текстом, а native controls сохраняются.

## Отложенные проблемы

### До подключения backend и AI

Нужно определить типизированный черновик портрета, который сможет содержать:

- подтверждённые ответы и пропуски;
- только разрешённые metadata голосовой записи и явный статус пропуска;
- дату рождения либо явный отказ;
- выбранные модули;
- идентификаторы preview и полного результата;
- состояние синхронизации и восстанавливаемые ошибки.

Этот контракт не следует помещать в текущий глобальный store автоматически. Сначала требуется решить срок жизни гостевой сессии, правила согласия и момент серверного сохранения.

### Архитектура экранов

- Перенос Landing и Start Portrait в feature-модули следует делать отдельной проверяемой задачей.
- Loading, empty и error состояния серверных экранов должны появиться вместе с контрактами API, а не как несвязанные локальные заглушки.
- Переходы-кнопки следует заменить на общий семантический link-подход без изменения визуального языка.

### Производительность

- Route-based lazy loading целесообразен перед заметным ростом числа экранов.
- Текущий production bundle: около 359 kB JavaScript без сжатия и 104 kB gzip.
- Мемоизация карточек и callbacks сейчас не обоснована: списки короткие, тяжёлых вычислений в render нет.
- Неограниченный список уведомлений требует политики до появления частых серверных событий.

### Тестируемость

- В первую очередь нужны проверки router history/focus, drawer/dialog, questionnaire reducer, voice lifecycle, birth-date validation и settings confirmations.
- MediaRecorder, MediaStream, AudioContext, timers и URL API уже локализованы достаточно, чтобы подменять их в тестах, но voice hook желательно разделять только после появления regression-набора.
- Недетерминированных демонстрационных данных не найдено; даты результата заданы явно, генерация управляется известными таймерами.

## UI и CSS

- Базовые `Button`, `Card`, `Input`, `Typography`, `Icon`, `Stack`, `Container`, `Surface`, `Divider`, `Badge`, `Spinner`, `Progress`, `Modal` и `Toast` остаются нейтральными и не содержат продуктовой логики.
- HTML-атрибуты прокидываются; `Button` и `Input` допускают `ref`, где это уже необходимо приложению.
- Нативная семантика button, input, progress, dialog, audio, radio и checkbox сохранена.
- Локальных цветов вне токенов и неиспользуемых CSS module classes не найдено.
- Breakpoints согласованы вокруг mobile, tablet, desktop и ultra wide; основные grid-колонки используют `minmax(0, 1fr)`.
- Глобальные transition tokens обнуляются при `prefers-reduced-motion`; отдельные сложные переходы также имеют локальные правила.
- Повторяющиеся CSS-паттерны зафиксированы как долг, но не объединялись во избежание визуального регресса.

## Состояние и ресурсы

- Product-data не помещены в глобальные `app`, `ui` и `session` stores.
- Derived state в основных feature-модулях вычисляется, а не дублируется без необходимости.
- Generation timeout очищается при смене стадии и размонтировании.
- Theme и media-query subscriptions снимаются корректно.
- Voice-модуль останавливает tracks, интервалы и timeout, отключает Web Audio nodes, закрывает AudioContext и отзывает Object URL.
- Blob и аудиоданные не записываются в storage, не логируются и не отправляются по сети.
- При уходе со страницы активная запись освобождается; повторное включение микрофона требует действия пользователя.

## Готовность к Sprint 3

### Готово

- feature-модули результата, профиля, истории и настроек принимают типизированные данные отдельно от UI;
- демонстрационные данные вынесены из компонентов;
- чистые validation и transformation functions можно проверять отдельно;
- preview и полный результат имеют самостоятельные модели;
- маршруты и дизайн-система стабильны для дальнейшей работы;
- текущий локальный путь не зависит от backend.

### Требует решения

- единый контракт и владелец состояния черновика портрета;
- серверные loading, empty, error и retry состояния;
- политика временного возрастного ограничения;
- семантическая модель ссылок для навигационных CTA;
- минимальный набор автоматизированных browser regression tests.

## Проверка

- `npm run lint` — успешно;
- `npm run format:check` — успешно;
- `npm run build` — успешно;
- `npm audit` — 0 известных уязвимостей;
- `git diff --check` — успешно;
- 24 локальные проверки чистой логики — успешно;
- 5 проверок light, dark и system theme — успешно;
- все 13 утверждённых URL, включая `/404`, и неизвестный URL напрямую отдаются dev server с HTTP 200; неизвестный pathname разрешается в компонент 404;
- статический граф импортов — 0 циклов;
- сетевой вызов из voice feature отсутствует;
- CSS-проверка не выявила локальных жёстко заданных цветов и неиспользуемых module classes.

Интерактивный browser-control в среде аудита был недоступен. Поэтому back/forward, реальный tab order, focus trap, разрешения микрофона, MediaRecorder на физическом устройстве и визуальное поведение на контрольных viewport проверены по коду, CSS, runtime URL и чистой логике, но не полноценным браузерным прогоном. Это ограничение нужно закрыть ручным smoke-test или автоматизированным browser regression-набором до публичного релиза.
